# 🏛️ BentHermes — AI Agent Dev-Lab on Azure using Terraform  
## ... The project previously known as ~~🦀~~ ~~BentClaw~~  

Deploys [Hermes Agent](https://hermes-agent.nousresearch.com/) on a single Azure Linux VM.
> No Bastion, no Key Vault — just a locked-down VM with a public IP and NSG-restricted SSH.

### 🏛️ Why Hermes?

OpenClaw was the original lab target, but it presented significant pitfalls — fragile config schemas across updates, opaque gateway auth, and a talent for creative self-destruction during overnight autonomous runs. After one too many mornings greeted by a broken gateway and a $100 token bill from a recursive lint-fix loop, the lab switched to [Hermes Agent](https://hermes-agent.nousresearch.com/) by Nous Research.

Hermes brings a few things OpenClaw never quite nailed:

- **Memory** — persistent, structured memory across sessions. It remembers your project, your preferences, and that one env var you always forget. No more re-explaining your entire codebase every Monday morning.
- **Skills** — reusable, self-authored `SKILL.md` modules loaded on-demand instead of cramming everything into a mega-prompt. *"OpenClaw follows a manual; Hermes writes its own."*
- **Self-improvement** — the `/learn` command lets Hermes study a workflow and synthesize a reusable skill from it. It literally gets better at its job while you sleep. (Just set a budget alarm first.)

OpenClaw is still available — uncomment its install line in `cloud-init.yaml` and rebuild the VM. See [Guide_OpenClaw.md](Guide_OpenClaw.md).

## 🧬 What you get

| Resource | Details |
|---|---|
| Resource Group | `rg-<project_name>-<location>` |
| VM | `Standard_B2s` (2 vCPU / 4 GB, burstable), Ubuntu 26.04 LTS, 128 GB Standard SSD |
| Networking | VNet `10.0.0.0/16`, VM subnet `10.0.2.0/24` (VM static at `10.0.2.8`) |
| NSG | SSH (22) locked to **your** public IP (auto-detected); OpenVPN (UDP 1194) open to public; Hermes + OpenClaw gateway ports optional |
| Public IP | Standard SKU, static, FQDN `<project_name>008.<location>.cloudapp.azure.com` |
| SSH key | Generated by Terraform, output as `ssh_private_key` |
| OpenVPN | peer-fingerprint mode server on the VM; `azureclaw.ovpn` written to the VM home dir |
| Software (cloud-init) | Hermes Agent (latest, `--non-interactive --skip-computer-use`), azure-cli, ffmpeg, openvpn, git, curl |
| Terraform tooling | Terraform 1.16.6 + TFLint 0.64.0, pinned official Linux AMD64 binaries with SHA-256 verification |
| Off-VM backups | Standard LRS / Hot Blob Storage in the VM resource group and region; private `hermes-backups` container |

Hermes is installed on first boot via cloud-init with `--non-interactive --skip-computer-use` (headless, no GUI driver). Run `hermes setup` yourself when cloud-init finishes.

**Estimated cost: ~$35/month** (VM ~$30, disk/IP minor). `terraform destroy` or deallocate the VM to stop compute billing.

## 🛠️ Prerequisites

- Terraform >= 1.6.0
- Azure CLI authenticated (`az login`)
- Resource providers registered (one time):
  ```
  az provider register --namespace Microsoft.Compute
  az provider register --namespace Microsoft.Network
  ```

## 🏗️ Deploy

```bash
cp terraform.tfvars.example terraform.tfvars   # fill in the ARM/sp values
terraform init
terraform apply
```

## 🛜 Connect

```bash
terraform output -raw ssh_private_key > ~/.ssh/azureclaw_key.pem
ssh -i ~/.ssh/azureclaw_key.pem <vm_localadmin_user>@$(terraform output -raw vm_public_name)
```

`~/.ssh/azureclaw_key.pem` works in both bash and PowerShell and inherits ACLs on Windows. If you save the key somewhere else on Windows, restrict its ACL (`icacls <file> /inheritance:r /grant:r "<DOMAIN>\<user>:R"`) or OpenSSH will refuse it ("UNPROTECTED PRIVATE KEY FILE").

## ✅ Verify

Wait ~10 minutes for cloud-init (apt upgrade + Hermes install), then in the VM:

```bash
tail /var/log/cloud-init-output.log
hermes --version
hermes doctor
```

When ready, finish setup interactively:

```bash
hermes setup
hermes gateway install
hermes gateway start
```

See [Guide_Hermes.md](Guide_Hermes.md) for the full post-deploy walkthrough (dashboard, API server, basic auth, etc.).

## Off-VM Hermes backup storage

`storage.tf` adds a StorageV2 account in the existing deployment's resource group
and region. For tacocat, use the original deployment inputs (`project_name =
"tacocat"`, `location = "southcentralus"`) and its existing Terraform state/backend;
the example defaults target a different deployment. The account name is derived
from the resource group ID, so no manually chosen global name or new provider is
needed.

- Standard LRS, Hot tier: low cost at this backup size, immediate restores and no
  minimum-retention penalties.
- Private container, HTTPS/TLS 1.2, Azure-managed encryption at rest, seven-day
  blob soft delete and no blob versioning.
- Storage firewall permits only the VM subnet through `Microsoft.Storage` service
  endpoints. The public endpoint remains enabled for that mechanism, but other
  networks and anonymous blob access are denied. No paid private endpoint.
- VM system-assigned identity gets `Storage Blob Data Contributor` on this
  container only. The uploader needs no storage key or SAS token. Azure account
  keys are not disabled; Terraform's existing provider authentication is unchanged.
- No lifecycle expiration rule: the upload job must preserve the existing union
  of seven daily, six Mon/Wed/Fri and four first/15th backups. A simple age-based
  rule would not implement that policy.

**Infrastructure only:** this configuration does not install or change the live
backup uploader/timer. A later integration should upload verified ZIPs after the
03:15 UTC backup, verify successful uploads before remote pruning, and retry
uploads on same-day reruns without deleting local backups on upload failure.
Account/container names and the container URL are available as Terraform outputs.
VM/disk failure is covered once uploads are configured; region-wide failure and
deletion of this resource group are not.

### Tooling and safe verification

The cloud-init bootstrap installs the pinned tools into `/usr/local/bin` using
checksums published with their official releases. Update the version, URL and
checksum together. Cloud-init normally runs once on a new VM; editing its embedded
`user_data` may cause VM replacement. Install tools directly on an existing VM
rather than reprovisioning it just for tooling.

```bash
terraform fmt -check
terraform init -input=false
terraform validate
tflint --init
tflint
terraform test
terraform plan -input=false -detailed-exitcode
```

The tests use mock providers and do not contact Azure or deploy resources. A real
plan still requires the original state/backend and actual deployment inputs,
including the four required `arm_*` credentials. Do not substitute placeholder
credentials or run a fresh stateless plan against existing infrastructure. The
deployment identity also needs permission to assign the container-scoped role;
data-plane operations require access from the permitted subnet. Review the plan
for any VM replacement before considering a separately approved apply.

## 🗝️ Access the gateway

The VM runs an OpenVPN server (peer-fingerprint mode, generated on the VM with openssl at first boot) on UDP 1194, open to any public IP. Fetch the profile after cloud-init finishes:

```bash
terraform output -raw openvpn_config_file   # prints the scp command
# backup option:
ssh -i ~/.ssh/azureclaw_key.pem <vm_localadmin_user>@$(terraform output -raw vm_public_name)
cat ~/azureclaw.ovpn > azureclaw.ovpn
```

Import `azureclaw.ovpn` into OpenVPN Connect (or `openvpn --config azureclaw.ovpn`).
Once connected, the services are reachable on the VM's private IP:

```bash
echo "Hermes gateway: http://$(terraform output -raw vm_private_ip):$(terraform output -raw hermes_gateway_port)"
echo "Hermes WebUI:   http://$(terraform output -raw vm_private_ip):$(terraform output -raw hermes_webui_port)"
```

Or tunnel over SSH (no VPN required):

```bash
ssh -i ~/.ssh/azureclaw_key.pem \
  -L 8643:127.0.0.1:8642 \
  -L 9120:127.0.0.1:9119 \
  <user>@<vm_fqdn>
```

Set `allow_hermes_gateway_public = true` or `allow_hermes_webui_public = true` in `terraform.tfvars` to allow those ports from your IP directly (re-apply required).

## 📊 Sizing notes

- `Standard_B2s` is the sweet spot for a single-user dev-lab, bursty workload (~$30/mo).
- Heavier use (multiple channels, big automations):
  - bump to `Standard_D2s_v5` (2 vCPU / 8 GB, ~$65/mo).
- cloud-init runs `apt update && apt upgrade -y`, installs packages, then installs Hermes; first boot takes ~10 minutes before everything is up.
- OPTIONAL: Uncomment `# OpenClaw` install in `cloud-init.yaml` to also install [OpenClaw](https://openclaw.ai)
